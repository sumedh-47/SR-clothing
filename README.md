# FASION

A fashion storefront built with React, Vite, Express, Node.js, and MongoDB/Mongoose.

## Run locally

1. Install Node.js 18 or newer.
2. From the project root, run `npm install`.
3. Run `npm run dev` and open the Vite URL printed in the terminal.

The API starts on port 5000. Without `MONGODB_URI`, it uses the included sample catalog and keeps orders in memory for development. To persist products and orders, copy `.env.example` to `.env`, set `MONGODB_URI` to your MongoDB connection string, then restart the API. On an empty database, the API inserts the sample catalog at startup.

## Storefront

Customers can browse by category, search products, sort by featured/newest/price/name, and save pieces to a wishlist that persists in their browser. The bag is also stored locally, so it remains available after a refresh. Saved items and bag contents are browser-specific; customer accounts currently sync profile and order history, not saved items or bags.

## Deploy publicly

The app is split into a Vite storefront and an Express API. A Vercel frontend deployment alone is not enough: deploy the API separately and set `VITE_API_BASE_URL` in the Vercel project to the API's HTTPS origin (for example, `https://sr-clothing-api.onrender.com`, with no trailing slash). Set the Vercel project root to `client`, build command to `npm run build`, and output directory to `dist`. The frontend uses this base URL for API requests and API-hosted product uploads; leave it unset for local development with the Vite proxy.

### Free static preview

The GitHub Pages workflow publishes a free, static catalog at `https://sumedh-47.github.io/SR-clothing/` whenever `main` is updated. It uses the included sample products and storefront copy; the bag and saved pieces are stored only in the visitor's browser. Checkout, customer accounts, admin, and order persistence are disabled, so this preview does not accept orders. The Admin-enabled deployment below uses a separate Vercel URL; it does not change the GitHub Pages preview.

### Free database-backed demo (Admin-only)

For a non-commercial college demo, the intended zero-cost setup is a Vercel frontend, a Render free web service, and a MongoDB Atlas free cluster. Free-plan limits and terms can change, so select only free options in provider dashboards and confirm the displayed cost before creating services. Vercel Hobby is intended for personal, non-commercial use.

The Render blueprint uses the free plan and has no persistent disk. Its service may sleep when idle, so the first request after a period of inactivity can take longer. Product, category, and storefront data persist in MongoDB Atlas, but files written to the Render service's local filesystem do not have durable storage. Newly uploaded product images can disappear after a restart or redeploy; use stable external image URLs or keep image files in the repository instead. Do not rely on free-tier uploads for permanent image storage.

No hosting service or database is created by this repository. In this Admin-only mode, customer accounts, order creation, and payment routes are disabled by both the storefront and API, and Razorpay credentials are not required.

Configure these values in the Render dashboard, not in source control or chat:

- `MONGODB_URI`: a remotely reachable MongoDB Atlas connection string.
- `CLIENT_ORIGIN`: the exact HTTPS Vercel site origin, with no trailing slash.
- `ADMIN_ID` and `ADMIN_PASSWORD`: administrator login; use a unique password of at least 16 characters.
- `ADMIN_TOKEN_SECRET`: generated by the Render blueprint.
- `COMMERCE_ENABLED`: set to `false` (also set by the blueprint).

The API refuses to start in production if required settings are missing, the database is local/unreachable, or the database connection fails; it will not silently switch to in-memory storage. The existing GitHub Pages site remains a static preview and does not connect to the API or database. The Admin sign-in screen can be opened there, but it cannot authenticate or edit data without the hosted API.

The current deployment files do not create hosting accounts, databases, payment keys, or a public domain.

### Deployment sequence

1. Use this existing GitHub repository; do not create a duplicate repository. Confirm the latest source is pushed before importing it into a host.
2. Create a MongoDB Atlas cluster and database user. Configure network access for the Render service and keep the Atlas URI private.
3. Import the repository into Vercel with project root `client`, build command `npm run build`, and output directory `dist`. Set `VITE_COMMERCE_ENABLED=false`; leave `VITE_STATIC_PREVIEW` unset. Deploy once to obtain the Vercel origin; API-backed catalog data will load after step 5.
4. Create a Render Blueprint from the repository. Select the free plan. Set `MONGODB_URI`, `CLIENT_ORIGIN` to the Vercel HTTPS origin, `ADMIN_ID`, and `ADMIN_PASSWORD`; keep `COMMERCE_ENABLED=false` and use the generated `ADMIN_TOKEN_SECRET`. Confirm the service remains on a free plan before creating it. Wait for `/api/health` to report `"database":"connected"`.
5. Copy the Render API's HTTPS origin into Vercel as `VITE_API_BASE_URL`, then redeploy the frontend.
6. Open `/admin` on the Vercel site and verify Admin sign-in, product editing, and storefront edits. Customer account, order, and payment API routes should remain disabled in Admin-only mode. Avoid relying on newly uploaded images being permanent on the free service.

To enable commerce later, explicitly set `COMMERCE_ENABLED=true` in Render and `VITE_COMMERCE_ENABLED=true` in Vercel, add the Razorpay API and webhook secrets to Render, and redeploy both services. Validate with Razorpay test credentials first; live charges require approved onboarding and live keys.

## Admin panel

Open `/admin` on the hosted Vercel site, or tap the storefront logo five times within 2.5 seconds, to reach the Admin sign-in screen. The actual admin dashboard requires the API-backed deployment; the GitHub Pages static preview cannot authenticate or make admin changes. For local development, set `ADMIN_ID`, `ADMIN_PASSWORD`, and a long random `ADMIN_TOKEN_SECRET` in `.env`, then restart the API before signing in. The panel includes sales and order summaries, product add/edit/remove controls, order status management, and a Storefront editor for homepage copy, navigation labels, announcement text, and footer content. Edit product details, buy and sell prices, and photos; the per-item profit or loss updates from the difference between the sell and buy prices. Upload up to eight JPG, PNG, WebP, or GIF photos per product (up to 5 MB each), replace the cover photo, and remove photos; customers can browse the product gallery. Product, hero, and story photos are served from `server/uploads`. Admin sessions are signed and expire after eight hours. Admin API routes require the session token; there is no public admin registration.

With MongoDB configured, product and storefront edits persist in the database. Without `MONGODB_URI`, catalog edits and storefront content use the development in-memory mode and reset when the API restarts; uploaded image files remain in `server/uploads`.

## Online payments

When commerce is enabled, checkout uses Razorpay, with UPI highlighted alongside the other available payment methods. Create API keys in the Razorpay Dashboard and set `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` in `.env` for local development or in Render for production. UPI availability depends on the payment methods enabled for your Razorpay account and whether the selected mode supports the method. The secret stays on the server; never add it to frontend code. For payment recovery when a customer closes checkout, configure a Razorpay webhook at `/api/payments/razorpay/webhook`, subscribe to `payment.captured`, and set the matching signing secret as `RAZORPAY_WEBHOOK_SECRET`. Test payments require Razorpay's test mode and test payment details. Live payments require live keys and a publicly reachable HTTPS deployment. Keep `COMMERCE_ENABLED=false` and `VITE_COMMERCE_ENABLED=false` for an Admin-only deployment.

To reset the MongoDB catalog to the sample products, run `npm run seed` after configuring `.env`. Build the frontend with `npm run build`.

## API

- `GET /api/health` reports API and database mode.
- `GET /api/products?category=Clothing&search=shirt` lists and filters products.
- `POST /api/orders` accepts `{ "customer": { "name", "email", "address" }, "items": [{ "product", "quantity" }] }`. Prices are looked up by the API, not trusted from the browser.
- Admin endpoints are under `/api/admin`; authenticate with `POST /api/admin/login` using the configured admin password.
